01 / PURPOSE

Turn scholarship rules into an understandable next step.

Finding a scholarship usually involves reading several pages of rules. This website asks relevant questions and compares the answers with the documented conditions for six selected Indian national scholarship routes. It then explains the outcome condition by condition.

The finished product contains an overview, a three-step eligibility form, a searchable catalogue, personal results, a saved shortlist, comparison of up to three routes, document preparation checklists, an exported text report and this guide.

What “fully functional” means here: the questionnaire, rule evaluation, filters, comparisons, local saving, checklist ticks and downloads work end to end. Scholarship applications, government identity verification and award decisions happen on the official portal. This version has no government account integration, server database, admin editor or automatic rule refresh.

“Smart” means the form adapts to the student’s study level and the engine explains rules transparently. It uses explicit decision rules, rather than an AI model or an invented probability of receiving money. It supports selected fresh-entry routes; most renewal routes and state or private scholarships are outside its coverage.

02 / USER WALKTHROUGH

Use the website in six simple steps.

  1. Start: choose “Check my eligibility” from the overview or open Eligibility checker in the navigation.
  2. Background: enter Indian-student status, gender, total annual family income in rupees and category. Use 300000 for ₹3 lakh. The category question supports the school marks relaxation.
  3. Education: select current study level, study mode and any relevant course or institution details. A technical student sees AICTE approval questions; a postgraduate sees institution eligibility; a school student sees school type.
  4. Final details: answer the questions shown for your route. “Not sure” preserves uncertainty. Enter 0 where a numeric condition does not apply, such as no gap; leave the optional certified-disability field blank if unknown.
  5. Results: choose Show my results. Open View details to read the reasons and tick the document preparation checklist. Filter or compare scholarships and save interesting ones with the heart button.
  6. Next steps: download the full report, confirm current rules on the linked official source and apply through NSP. Do not treat a preliminary result as confirmation of an award.

Try the example profile if you want to explore without entering your own information. It describes a first-year female technical student with family income of ₹3 lakh. Remember my profile is optional and saves only to the current browser.

03 / WEB BASICS

Three languages make the app work.

TechnologyThink of it asIts actual job here
HTMLThe structure of a houseDefines navigation, the page container, dialogs, guide text and diagrams.
CSSThe interior and layoutSets colours, spacing, typography, cards, focus outlines and phone layouts.
JavaScriptThe switches and moving partsShows the right form, validates answers, evaluates eligibility and responds to clicks.

A browser reads these files and displays the website. A web server delivers them when a visitor opens a URL. A static website can still be interactive: “static” refers to the files being delivered, not to the absence of functioning buttons.

The frontend is what runs in the browser. A backend would process requests on a remote server. The eligibility engine in this project is frontend code. This makes it fast, inexpensive to host and usable without sending profile answers to an application server.

Node.js is a way to run JavaScript outside a browser. It is used here for the local preview server and automated tests. Visitors do not need Node.js installed to use the deployed site.

04 / ARCHITECTURE

Where each part runs.

The application does not have a database. The scholarship catalogue is a small array in the source. A hosted copy of that array is delivered with the website. Updating a scheme means editing and republishing the files.

Hosting access controls protect who can open the deployed site. The initial deployment is private to the owner. This hosting access is separate from local profile storage: there is no student account system and no automatic synchronization between devices.

06 / CREATION PROCESS

How the product was created.

  1. Define the intended experience. The main job was matching a student with understandable scholarship possibilities. India was selected. The design avoids unnecessary account creation or identity-document collection.
  2. Research official sources. NSP’s current scheme list, linked AICTE PDFs, Ministry of Education material and UGC guidance were checked. The catalogue records sources and a check date. Old restrictions that conflict with new portal announcements are treated as review cases.
  3. Design the interface. A lavender-and-white visual system, persistent navigation, clear cards, a friendly graduation illustration and readable form labels were created. Narrow screens use a horizontal navigation row and stacked cards.
  4. Represent the rules. Scheme metadata was added to engine.js. Each scheme has explicit conditions and a check function. The engine produces structured results, so the interface can show reasons without duplicating the decision logic.
  5. Build the interactions. app.js implements the questionnaire, dynamic fields, navigation, search, filters, saved items, comparison dialog, checklists and text-report generation.
  6. Write beginner documentation. This guide describes the implementation and contains architecture, user flow, decision and storage diagrams. It can be downloaded as HTML or printed to PDF.
  7. Validate the behaviour. Automated tests cover income limits, disability boundaries, lateral entry, unknown answers, school relaxation, postgraduate age and deadline expiry. Browser checks exercise the visible workflow where preview access permits it.
  8. Prepare publication. A private Site identity is stored in the hosting manifest. The exact source is synchronized and packaged before the matching version is deployed. Secrets are kept out of source files.

The implementation uses no framework because this scope does not require one. Fewer dependencies make the first version easier for a beginner to understand and run. If future features need a shared database or accounts, the architecture will need to expand.

07 / DATA MODEL

Data is stored as small JavaScript objects.

An object groups named values. An array groups multiple items. The catalogue is an array of scheme objects. A profile is another object containing the student’s answers.

// Short example of scheme metadata
{
  id: 'pragati',
  name: 'AICTE Pragati',
  type: 'Merit',
  amount: 50000,
  levels: ['ugtech', 'diploma'],
  checked: '2026-10-14',
  deadline: '2026-10-31',
  sources: [['Degree guidelines', 'official PDF URL']]
}

The id is the stable identifier. Saved items use this value rather than the display name, so changing a scholarship’s wording does not invalidate a saved item. amount is a representative annual value, while award is the human-readable benefit description. CSSS has different rates by year, so its display describes the range.

// Example of a partial student profile
{
  citizen: 'yes',
  gender: 'female',
  income: '300000',
  level: 'ugtech',
  year: '1',
  mode: 'regular',
  aicte: 'yes',
  otherAid: 'no'
}

HTML forms return text strings, even for number fields. The engine converts relevant numeric strings into numbers and checks they are finite. An empty field is not silently converted into zero. This distinction matters: unknown income is different from zero income.

Important field names include top20 for the Class XII board-percentile condition, gap for the admission gap, nmmsSelected for state selection, and pgInstitution for the postgraduate scheme’s specific institution conditions. The form asks only the fields relevant to the selected study route.

08 / USER FLOW

What happens from opening the website to taking action.

The app uses the URL fragment for navigation, such as #checker, #browse and #saved. Changing the fragment triggers a hashchange event. The application replaces the contents of the main page container with the selected view.

The step number lives in JavaScript memory. Answers are captured before advancing or going back. Changing the study level clears dependent answers, preventing stale technical-course information from affecting a newly selected school or postgraduate route.

09 / DECISION LOGIC

A condition has three possible outcomes.

Rule outcomeMeaningExample
PassThe reported answer satisfies this rule.₹3 lakh income is within the ₹8 lakh ceiling.
FailThe reported answer does not satisfy this rule.39% certified disability is below Saksham’s 40% minimum.
ReviewThe answer or current requirement needs confirmation.The student does not know whether both course and institution are AICTE approved.

The evaluator adds every screened condition to a list. It does not stop at the first failure. This allows students to understand several reasons at once. Each condition records its label, status and explanation.

if (any condition fails) {
  result = 'Does not match';
} else if (any condition needs confirmation) {
  result = 'Needs review';
} else {
  result = 'Preliminary match';
}

There is no weighted percentage or “chance of success”. Scholarships often have mandatory conditions: passing seven conditions cannot compensate for failing an eighth. Likewise, a person may meet the basic conditions but not be selected because of merit ranking, available slots or documentary checks.

Two rules need special care.

Percentile versus percentage: CSSS refers to standing above the 80th percentile among successful candidates in the relevant board stream. A marks percentage describes points earned in an examination. The app asks about the board-percentile condition rather than treating 80% marks as proof.

Other financial aid: older scheme PDFs restrict concurrent assistance, but NSP announces merit and welfare applications from 2026–27 subject to scheme criteria. If other aid is reported or unknown, this app produces a review condition. It does not promise that a combination is permitted and does not automatically reject every combination using old rules.

CSSS fresh-entry academic rules are included for information, but the current portal lists renewal applications only. Its application availability therefore creates a review condition even if the student passes the screened fresh-entry academic rules.

10 / WORKED EXAMPLE

Follow one student through the engine.

Imagine an Indian female student in the first year of a regular technical undergraduate degree. Family income is ₹3 lakh. Both course and institution are AICTE approved, the institution is recognized, there is no gap, no other girl in the family receives Pragati, and the student receives no other assistance. She reports no certified disability or Swanath family circumstance and confirms the CSSS board-percentile condition.

RouteWhat the engine findsResult
PragatiThe reported fresh-entry, gender, income, approval, family-beneficiary and gap conditions pass.Preliminary match
SakshamThe certified-disability threshold is not met.Does not match
SwanathNo specified family circumstance applies.Does not match
CSSSThe screened academic conditions pass, but fresh application availability needs confirmation.Needs review
NMMSSThe student is in college, outside this school fresh-entry route.Does not match
PG scholarshipThe student is not in a first-year postgraduate programme.Does not match

The example button loads this scenario. Change income to ₹8,00,001 and Pragati no longer matches. Change AICTE approval to “Not sure” and Pragati becomes Needs review. These changes demonstrate mandatory thresholds and uncertainty handling.

The results are evaluated from the information entered. The app does not know whether a reported certificate is valid, whether a deadline was extended or how a student ranks among other applicants. Those remain official checks.

11 / SOURCES AND COVERAGE

The six routes and their official references.

The catalogue contains selected national routes, not every scholarship in India. Degree and diploma variants of the AICTE schemes are grouped in the same route with separate source links. Current dates are snapshots from NSP’s 2026–27 scheme list, checked on 14 October 2026.

  • Pragati: degree guidelines and diploma guidelines. Technical education support for girls. The checker screens income, entry year, approvals, gap and the family-beneficiary limit.
  • Saksham: degree guidelines and diploma guidelines. Technical education support with a certified disability threshold. UDID requirements should be confirmed on the portal.
  • Swanath: May 2025 guidelines. Includes the updated parental critical-illness and specified accident circumstances, alongside orphan, COVID-19 bereavement and martyr-ward categories.
  • PM-USP CSSS: 2025–26 Ministry FAQ. The form models fresh-entry rules. Existing awardees need the official renewal rules; this checker does not determine renewal eligibility.
  • NMMSS: revised Ministry guidelines. Class VIII screening is readiness for the state selection route. Class IX screening requires state selection and school marks. State exam deadlines are separate from the NSP award deadline.
  • National Scholarship for PG Studies: detailed UGC guidelines. Age is screened as below 30 at admission, following the detailed wording. Current eligible institutions and merit selection must be confirmed.

The listed NSP student application deadline is 31 October 2026 for these routes, with CSSS listed for renewal. After that date, the app displays “Listed deadline passed”. It does not infer that a scheme has permanently closed or automatically fetch extensions.

Application-versus-benefit combination rules use the current NSP announcements alongside the older scheme documents. Dates, document checklists and eligibility rules should be rechecked when the catalogue is updated.

12 / FEATURES UNDER THE HOOD

How the working features are implemented.

Search and filters

The search input compares a lowercase search term with each scheme’s name, authority, tag and description. Type and study-level filters narrow the same catalogue. Result screens additionally filter by match, review or mismatch. Reset filters clears all filters. An empty view explains what to do next rather than showing a blank screen.

Saving and checklists

The heart button toggles the scheme’s stable ID in the saved array. The Saved screen reads that array. Checklist tick keys combine the scheme ID and item position, for example pragati:0. They record preparation progress, not an uploaded or verified document.

Comparison

Checkboxes add up to three IDs to an in-memory comparison list. With at least two selected, the comparison button opens a table showing support, type, main conditions, entry scope, screening status and source link. Selected amounts are never added into a combined entitlement.

Results and reports

The interface calls evaluate(scheme, profile) once per catalogue item. The results view sorts preliminary matches first, followed by reviews and mismatches. Every route stays available, so a student can see why a scheme was excluded.

Download full report creates a text file containing the profile, all six outcomes, all rule explanations, preparation documents, official links, source-check date and listed deadlines. It uses a browser Blob, a temporary URL and a download link. No report-generation server is involved. The Print results button prints the current filtered screen; the full download always contains all six routes.

Accessible and responsive interface

Inputs have labels, dialogs have titles, buttons show keyboard focus and changing pages focuses the main content. Toast messages use an accessible status region. Native form validation checks required fields and numeric ranges. Reduced-motion settings suppress transitions. CSS media queries change the desktop grid into narrower and phone layouts.

13 / STORAGE AND PRIVACY

What is remembered, and where.

localStorage is a small storage space belonging to the website in the current browser. The key used by this app is scholarship-compass-v1. Its value is JSON text containing saved IDs, checklist flags and an optional profile.

Without Remember my profile, answers are held in memory and disappear on a full reload. With Remember enabled on final submission, the profile is saved and restored on later visits. Restored answers must be submitted again to generate fresh in-memory results. Editing a remembered profile does not save new values until the questionnaire is submitted.

Local storage is not a secure vault. On a shared device, another user of the same browser can open the profile. Use the privacy control to clear app data. Start fresh removes the remembered profile and resets the questionnaire; it does not remove the shortlist or checklist ticks.

No name, Aadhaar number, bank account number or document upload is requested. Profile answers are not sent to an application backend. Visiting the hosted site, loading Google Fonts and opening official links still create normal network requests; the hosting service, font service and official portals have their own policies. Income, disability and family circumstances should be entered thoughtfully on a shared device.

14 / RUN IT YOURSELF

Start with the downloadable source.

  1. Extract the final project ZIP to a new folder. This guide is included as your personal local learning file.
  2. Install Node.js from its official website if you want the local preview server. The website itself has no third-party JavaScript package dependencies.
  3. Open a terminal in the extracted project folder, where server.cjs is located.
  4. Run the command below and open the printed URL in your browser.
node server.cjs

Local: http://localhost:4173

Keep that terminal open while using the preview. Press Ctrl+C to stop it. If the port is already used, close the other server or change the port number in server.cjs. You can also open dist/index.html directly for a basic local check, but browser storage behaviour can vary for files; an HTTP preview is preferable.

Make a first edit

Open the files in a text editor. For wording and interaction labels, edit app.js. For colours, edit the CSS variables at the beginning of style.css. For scheme facts and logic, edit engine.js. Save the file and refresh the browser. Changes in your local folder do not affect the deployed site until you republish.

Hosting elsewhere

This site can be served by a host that supports static HTML files. Upload the contents of dist so index.html is at the served root. No API key or database is required. Keep guide.html and source-code.zip available if you want their download buttons to work.

For Sites publication, the project uses a separate hosting manifest with the registered project ID and static.directory set to dist. Source synchronization and deployment should use that existing identity for subsequent updates. The portable download intentionally excludes it.

15 / QUALITY AND MAINTENANCE

Keep the checker accurate as rules change.

Run the automated checks from the project root:

node tests.cjs
node --check dist/app.js

The supplied test suite contains 41 rule checks. These include exact income thresholds, values just above them, 40% versus 39.99% disability, known and unknown lateral entry, gap limits, other assistance, updated Swanath categories, CSSS availability, school category relaxation, PG age 29 versus 30 and expiry of the listed deadline in India’s time zone.

These tests exercise the rule engine. They do not prove that government sources remain current and do not replace browser testing. After a change, also complete a questionnaire, open details, save and unsave a scheme, tick a document item, compare two schemes, use filters, download a report and test a narrow screen.

Update a scholarship safely

  1. Read the current official scheme document and the latest NSP announcements. Confirm whether it is a fresh or renewal route.
  2. Write down what changed: threshold, covered year, institution conditions, benefit, deadline or evidence.
  3. Update the matching catalogue fields and evaluator in engine.js. Preserve stable IDs unless intentionally creating a different scheme.
  4. Update form fields in app.js if a new answer is needed. Avoid leaving a new mandatory rule with no question.
  5. Add tests for the exact new boundary and an unknown answer. Test different routes to catch unintended effects.
  6. Update the check date, explanatory copy and guide. Republish the exact tested source.

Add another route

Create a new catalogue object with a unique ID, name, type, study levels, sources, dates, benefit and preparation documents. Add the scheme’s conditions to the evaluator. Add relevant questions and tests. Adding a display card alone does not create working eligibility logic.

16 / NEXT STEPS

Understand the limits before extending the project.

Useful future additions include verified state schemes, separate renewal questionnaires, a properly secured admin editor, a server database for reviewed catalogue updates, multilingual labels and optional user accounts for cross-device shortlists. None of these features is part of this version.

A database or account system changes the privacy responsibilities. Financial and disability-related data should not be collected merely because a backend becomes available. If live rule updates are introduced, keep official source provenance, review dates and change history; automatic scraping alone is not a reliable eligibility authority.
